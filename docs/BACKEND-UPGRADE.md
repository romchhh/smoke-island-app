# Обновление админ-бота, остатков и заказов

## Запуск

Нужен Node.js 22+ и MongoDB replica set (MongoDB Atlas поддерживает транзакции). Перед выкладкой сделайте резервную копию базы. Обновляйте backend и frontend вместе: старый frontend не резервирует корзину.

В папке backend выполните `npm ci`, затем `npm test` и `npm run test:integration`. Последний тест запускает отдельную временную MongoDB, может скачать бинарник и не использует рабочую базу или Telegram. Запуск сервера: `npm start`. Проверка доступности: `/api/health`.

Railway должен собирать папку backend, где находится package.json (Root Directory = backend при загрузке корня проекта). Альтернатива: загружайте именно backend через Railway CLI с настроенным path-as-root. Используйте существующий сервис, проверьте `railway status` перед `railway up`. Секреты задавайте через Railway Variables, не отправляйте их в чат или репозиторий. Frontend публикуется отдельно; его rewrite `/api/v1` должен вести на актуальный backend.

Не запускайте две копии admin-бота с одинаковым токеном одновременно: Telegram long polling будет конфликтовать.

## Админ-бот

После `/start` доступны кнопки:

- **Добавить товар → Точечно**: изображение через скрепку → название → категория → цена в zł → разновидности/остатки → плашка. Slug создаётся автоматически. Изображение хранится в MongoDB и доступно через API. Форматы PNG/JPEG/WebP, до 5 МБ. Номер шага и черновик сохраняются на 30 минут; `/cancel` отменяет.
- **Добавить товар → Списком**: до 30 строк, каждая строка — товар. Весь список проверяется до сохранения, сохраняется транзакцией.

```text
Наушники Aurora | Audio | 65.50 | Biały - 10; Czarny - 2 | NOWOŚĆ | https://example.com/photo.webp
Powerbank Core | Zasilanie | 120 | Srebrny - 4; Czarny - 8 | NONE
```

Ссылка на фото в списке необязательна. Для фото через Telegram используйте точечный мастер. Цена — zł, а в базе priceMinor — гроши: 65.50 = 6550. Действующая Smart Cena по прежней тарифной сетке продолжает применяться при заказе; отдельного редактора тарифов в этом обновлении нет.

- **Наличие**: категория → товар → ответ `Biały - 8, Czarny - 2` или с новой строки. Указывается новый физический остаток, не прибавление. Нельзя поставить меньше уже зарезервированного. Показываются физический, резерв и доступный остаток.
- **Промокод**: `RAB10, 10.00, 2026-12-31`. Скидка фиксированная в zł, дата YYYY-MM-DD включительно по UTC. Код действует до истечения/отключения; лимита одноразового использования у обычного промокода нет.
- **Приз**: Start / Base / Exclusive → точное название или slug существующего товара/приза. Base соответствует прежнему API-tier Premium. Выбранная модель становится постоянной наградой; её разновидность выбирается из доступных.
- **Создать приз**: кейс → фото → название → стоимость `65 zł`, `10 %` или `20 pkt`. Приз в zł — отдельная бесплатная награда без складского списания. Для физического складского товара используйте «Приз» с существующим товаром. Процентный приз создаёт персональный промокод на 90 дней, pkt начисляются один раз при получении. Обычная анимация открытия сохраняется, стоимость открытия кейсов сохранена.

Управление каталогом/призами разрешено перечисленным TELEGRAM_ADMIN_IDS и пользователям ADMIN/SUPER_ADMIN. MANAGER работает с заказами и поддержкой.

## Резерв и подтверждение

Корзина резервируется сервером по разновидностям. Доступный остаток = физический минус резерв. Изменения корзины проверяются на сервере; конкурентный запрос получает предупреждение с доступным количеством. После четырёх часов отсутствия активности резерв корзины снимается; frontend очищает обычные позиции при следующей проверке. Фоновый опрос сам по себе не продлевает резерв. Очистка запускается каждую минуту и при операциях с каталогом/корзиной/заказом.

После оформления резерв переводится в заказ и сохраняется до подтверждения или отмены менеджером. Четырёхчасовой срок относится к корзине, не к оформленному заказу. Подтверждение атомарно списывает физический остаток и резерв, начисляет 3% от итоговой суммы целыми баллами (округление вниз). Повторное нажатие не повторяет списания/начисления. В Telegram остаётся кнопка «Заказ подтвержден» без изменения состояния при повторном нажатии (Telegram не поддерживает настоящие disabled inline-кнопки).

Существующие заказы считаются legacy: их остатки были списаны старым кодом, поэтому повторно не списываются. Исторические данные и старые баллы автоматически не пересчитываются.

Сообщение заказа содержит контакт, город, адрес/код пункта, разновидности, промокод и итог. Обращение со страницы принятого заказа содержит номер заказа; доступ к нему проверяется по владельцу.

## Безопасность и границы проверки

Добавлены проверки прав, владельца заказа/награды, Origin для изменяющих API-запросов, ограничения частоты, проверка изображений по содержимому, ограничения размеров, атомарные остатки и защита повторных финансовых операций. Ошибки API не возвращают внутренние сообщения сервера. Зависимости проверены npm audit без известных уязвимостей на момент проверки.

Это не гарантия отсутствия краж и не полный аудит облачной инфраструктуры. Перед production отдельно проверьте:

- NODE_ENV=production; CORS_ORIGIN и FRONTEND_URL содержат только реальные HTTPS-домены магазина, без `*`.
- JWT_SECRET и SESSION_SECRET — разные случайные секреты не короче 32 символов; токены ботов доступны только backend. Если ранее публиковались, замените их.
- Atlas: отдельный пользователь только для базы магазина, TLS, минимальные сетевые разрешения; резервные копии и проверка восстановления.
- Railway/Vercel/Telegram: 2FA, ограниченный круг администраторов, отсутствие секретов в логах и клиентском коде; лимиты расходов и мониторинг ошибок.
- Проверка в реальном Telegram: загрузка фото, открытие меню, доставка заказа в правильный чат и ответа менеджера клиенту. Автотесты используют заглушку Telegram и не отправляют реальные сообщения.

Новые коллекции создаются приложением; резерв не использует MongoDB TTL-удаление, чтобы остаток не терялся без возврата. Для нескольких экземпляров приложения проверки безопасны транзакционно; лимитирование запросов пока локально каждому процессу.
